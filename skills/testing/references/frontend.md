## 2. Frontend / UI

### 2.1 Fields and Forms
- **Input types** matched to purpose (text/email/tel/url/number/password/search/date/file…); mobile virtual keyboard follows `inputmode`/`type`; number — spinners, step, mouse wheel, e/E/+/−/decimal separator; visual type matches the actual type.
- **Input masks/autoformat:** phone (+1 vs local prefix formats, paste with varying separators), date (dd.mm.yyyy, invalid 31.02/13th month), card (grouping, BIN, Luhn, CVV); cursor does not jump to the end when editing mid-value; Backspace across a separator; paste longer than the mask; mask does not break copying.
- **Length limits:** maxlength N−1/N/N+1 (block or truncate), counter matches; minlength; paste longer than the limit (truncate, not reject); emoji/surrogate pairs in the count; 10k+ characters without freezing; frontend vs backend limit.
- **Special chars/unicode/RTL:** `< > & " ' \` / \\` escaped; HTML tags not executed; emoji (ZWJ, flags, modifiers); RTL and mixed LTR+RTL; normalization (NFC/NFD); zero-width; homoglyphs; long words without spaces (word-break).
- **Paste/autofill:** paste with spaces/line breaks/tabs (trim), formatted text (strip formatting), into a masked field; browser autofill lands in the correct fields; **autofill often does not fire the `input` event → field looks "empty" to live validation**.
- **Whitespace/trim/case:** spaces-only in a required field = empty; leading/trailing trim; NBSP/tab/line break in a single-line field; email lowercased, name/password case preserved.
- **Keyboard/focus:** Tab order follows the visual flow; Enter = submit/next (per design, no double submit); Esc; arrows/Home/End in dropdowns/date pickers; autofocus on the first field, focus returned after a modal; wrong keyboard layout when Latin input is expected.
- **Validation and errors:** timing (live/on-blur/on-submit per spec); don't paint an untouched form red before interaction; error clears once fixed; message specific (not "Error 422"); focus/scroll to the first invalid field; submit disabled vs always active; double-submit protection (loader/disable); server error maps to the field; data preserved on error.
- **Required/dependent fields:** conditional requiredness; cascading dropdowns (country→cities, dependent reset); mutually exclusive/interdependent (date "from" ≤ "to"); hiding/showing fields does not lose entered data; totals recalculated.
- **Reset/persistence:** "Clear" resets to defaults (not to empty); draft (localStorage/server) restores; beforeunload on unsaved changes; bfcache on Back; resubmission after refresh (POST).
- **disabled vs readonly:** disabled — not editable/not in tab order/not submitted; readonly — in tab order and submitted; states visually distinct; placeholder ≠ value.
- **Dropdowns/multiselect:** native vs custom; search (case-insensitive, partial match); "nothing found"; long list (virtualization/perf at 1000+); chips for selected items, limit N; grouping, disabled options; keyboard selection; positioning near an edge (flip/shift); duplicate/empty options.
- **Counters:** real-time, correct on paste/delete; color change near the limit; count emoji the same way as maxlength.
- **REPEATING BLOCKS AND DYNAMIC COLLECTIONS** (add/remove N participants, items, addresses, files). A common gap: people check "added one" and "hit the limit", but never submit with the intermediate counts nor inspect the payload.
  - **Every count in the range is submitted and verified against the payload:** 0, 1, 2, … maximum. Not just the boundaries — array-assembly bugs typically surface at 2-3 elements. Check the NUMBER of elements and the FULL composition in the request, not merely that it succeeded.
  - **Unique data in every block.** Fill blocks with distinguishable values (Alpha/Beta/Gamma, different dates) — identical data hides swapping, off-by-one shifts and duplication. Match "block ↔ payload element" by name.
  - **Deleting BEFORE submit is a mandatory scenario, not just a UI check.** Delete from the start, from the middle and from the end, then submit and confirm the payload carries exactly the remaining set. Middle deletion is the main risk: with index-based `key` the framework loses the data-to-block mapping.
  - **Renumbering and headings** after deletion; the add button hiding/appearing at the limit and returning after a deletion; attempting to exceed the limit by request, bypassing the UI.
  - **Format conversion on EVERY element:** dates (DD.MM.YYYY → ISO), masks, casing. Use values where day and month are distinguishable (11.01, 22.02) — with 01.01 a swap is invisible.
  - **Validation inside blocks behaves as in the main form:** required, allowed characters, boundaries, length limits — verify on at least one added block, not only on the primary fields.

### 2.2 Visuals and States

> **Accessibility is out of scope for this checklist.** WCAG criteria, screen readers,
> `aria-*`, roles, the visible focus ring, contrast, `prefers-reduced-motion`,
> `prefers-contrast`, forced-colors and 200% zoom are a separate discipline - if a11y
> is in your scope, use a dedicated checklist instead of stretching this one.
> Hover / focus / disabled stay here as UI behaviour: cursor and visual response on
> hover, focus reaches the element and Enter/Space activates it, disabled is not
> clickable. "There must be a visible focus ring" is an a11y requirement, not a
> UI-state one - keep it out of expected results.

- **All states of every interactive element:** rest, hover, focus (focus reaches the element, Enter/Space activates it), active/pressed, disabled, loading, selected/checked, error/invalid, read-only. Verify hover **empirically** (real hover + computed-style diff), don't trust `:hover` in the stylesheet. On touch — no "stuck" hover. Disabled is not clickable/does not submit on Enter, cursor `not-allowed`. Loading: spinner inside the button, repeat click blocked, dimensions don't "jump". Combinations (hover+focus, disabled+loading, error+focus) behave predictably. States inside portals/overlays work the same.
- **Comparison against the design (Figma):** texts character-for-character (case, punctuation, guillemets, NBSP, ellipsis character); icons (set/stroke weight/size/color/filled-outline); sizes/spacing/padding/gap/click target — numerically (DevTools), not by eye; typography (family/size/weight/line-height/letter-spacing/color) per design token; alignment (icon+text baseline, grid); radii/border/shadows numerically. Take numbers from the design EXPORT plus arithmetic, not from the MCP text dump: the size of a nested raster is not the size of its frame, and `sizing: hug` containers expose no height at all. **Discrepancies → question for analyst/designer.**
- **Design-token consistency:** one "black"/"accent" across screens (no #000 vs #0A0A0A); uniform radii/shadows/font/size scale; 4/8-pt spacing grid (no 7/13/18px); identical dimensions for same-type controls; a single hover/focus/disabled pattern.
- **Overflow/wrapping:** long text in a button/chip/heading (wrap vs ellipsis per design); long word/URL does not overflow (`word-break`); line-clamp truncates correctly; placeholder longer than the field; long values in tables (tooltip); dynamic content (empty/long/emoji/RTL); large numbers (999+, 1 000 000); text at 200% zoom.
- **Image cropping on EVERY breakpoint.** `getBoundingClientRect()` on an `<img>` returns the size of the ELEMENT, not the area of the painted image: with `object-fit: contain/cover` the two diverge, so "the image matches the container" proves nothing. Compute what is actually painted from `naturalWidth/naturalHeight` and the container ratio (contain → letterboxed with empty bands, cover → filled with cropping) and compare the framing against the mockup BY EYE on every viewport. The same file changes behavior when the container ratio changes: where the file ratio matched the container it fills the block, on another breakpoint it is letterboxed and the subject shrinks relative to the mockup. The reverse hurts too: `cover` instead of `contain` crops away meaningful parts of the frame (faces, logos, captions).
- **Z-index/portals/overlays:** modal/dropdown/tooltip/toast above everything including the sticky header; correct stacking of multiple overlays; backdrop intercepts clicks, scroll-lock without a "jump"; close via backdrop/Esc/close button + focus returns to the trigger; dropdown near an edge (flip/shift), not clipped inside an `overflow:hidden`/`transform` parent.
- **Transient/loading:** mock a delay (route/throttling) and freeze the state — spinners, skeletons, progress, disabled buttons; skeleton geometry = content (no layout jump); no flicker "empty→skeleton→empty→data"; optimistic updates with rollback on error; long request (progress/cancel/timeout instead of an eternal spinner); parallel loads don't shift the layout.
- **Animations:** duration/easing per the design; the properties that actually change are the ones being animated (a common gap: `transition-property` omits `width`/`height`, so the box snaps to its final size while only background and padding ease in - check frame by frame, not by eye); no jank or "jump"; does not block interaction; open/close symmetry without clipping content; no infinite animations while off-screen; reserve space against CLS.
- **Dark theme:** no white flashes (background/inputs/overlays/iframe), no black-on-dark; icons/SVG recolor via `currentColor`; shadows replaced with border/highlight; states distinguishable; on-the-fly switching without flash or reload, persisted, respects `prefers-color-scheme`.
- **Empty states/toasts:** empty (illustration + text + CTA), distinct from error and loading; "no data" vs "nothing found for this filter" — different texts/actions; toasts (position, auto-dismiss, manual close, stacking, don't cover important content); inline vs toast vs modal by purpose.
- **VISUAL COMPARISON IS MANDATORY (common gap):** DOM, `innerText`, the accessibility snapshot and computed styles show structure, text and behavior, but NOT appearance. Running only through them misses a whole class of defects: the wrong component variant (primary instead of outline, grey fill instead of white with a border), broken spacing/fonts/radii, swapped illustrations. For every state you verify, take a screenshot of the implementation and look at it next to the mockup. A screenshot that failed to save is a blocker for that step, not a reason to move on. Computed styles prove the diff AFTER your eye caught it.
- **States absent from the DOM:** hover, focus, active, disabled on every interactive part - verify by hovering/focusing with a screenshot.
- **Instrumented checks:** capture computed styles via `browser_evaluate`/DevTools for an exact diff (not eyeballing screenshots); screenshot snapshots of key states with mock data (mask dynamic parts); rendering with fonts not yet loaded (FOUT/FOIT) and images blocked (alt/placeholders); console free of render errors (React keys, hydration mismatch), no 404s for fonts/icons.
- **Driving controlled inputs (React/Vue):** set the value via the native setter + dispatch input/change events, otherwise framework state will not update; type masked fields character by character instead of pasting; re-renders invalidate element refs/ids — re-locate elements afterwards.

### 2.3 Responsive and Cross-Browser
- **Canonical Desktop resolutions:** 1920×1080 (reference), 1536×864 (common laptop, 125% scale), 2560×1440 (2K — stretching, container max-width, side margins); additionally 1366×768, 1440×900.
- **Canonical Mobile:** 414×896 (iPhone 11/XR), 360×800 (average Android), 393×873 (Pixel 7), 430×926 (iPhone 14/15 Pro Max); additionally 768×1024 (iPad, tablet/desktop boundary). Take the minimum tested width from the project's requirements (usually 360; narrower ones like 320 — only if the project explicitly supports them).
- **Breakpoints:** render exactly at the boundaries (767/768, 1023/1024, 1279/1280) — no "jumps", clipping, or duplicate desktop+mobile menus; smooth resize from the minimum supported width up to 1920 (the reflow moment, no overlaps/collapse to 0).
- **Horizontal scroll (critical):** no horizontal scroll on body/containers at any resolution (fixed px widths, long URLs, wide tables, negative margins, `100vw` with a scrollbar, images without `max-width:100%`).
- **Reflow:** multi-column → single column (visual order = DOM, `order` not broken); sidebar moves below/into the burger; menu → burger; tabs → accordion/scroll; hiding labels/columns, table replaced by cards, filters into a bottom sheet; primary buttons full width; sticky CTA does not cover content/safe-area.
- **Touch:** targets ≥44×44 (iOS)/48×48 (Android) with spacing; swipes/sliders/pull-to-refresh/long-press; momentum scroll; hover functionality reachable via tap, no stuck hover.
- **Orientation/keyboard:** portrait↔landscape without clipping; landscape on a short screen does not hide the CTA; virtual keyboard does not cover the field (scroll it into view); `100vh` does not "jump" (use `dvh`/`svh`).
- **Zoom/font scale:** 200% zoom — single column without horizontal scroll, nothing clipped; 400% at 1280px; enlarged system font does not break layout; pinch-to-zoom not blocked (`user-scalable=no` is an antipattern).
- **safe-area/notch:** `env(safe-area-inset-*)`, content not under the notch/home indicator in portrait and landscape.
- **Cross-browser matrix:** Chromium (Chrome/Edge), WebKit (Safari desktop + iOS), Firefox; on iOS all browsers = WebKit. **WebKit specifics:** `position:sticky` in tables, `gap` in flex, `backdrop-filter`, `100vh` (address bar), `date`/`time` inputs, `border-radius`+`overflow:hidden`. **Firefox:** scrollbars, custom checkboxes, number spinners, sub-pixel fonts, `<details>`. **iframe:** scroll/focus on iOS, height on mobile, sandbox.
- **Misc:** `mask-image`/`clip-path`/`mix-blend-mode` (fallback in WebKit/FF); WebP/AVIF fallback, `srcset`/`sizes` per DPR; FOUT/FOIT, `font-display`; sticky header, scroll-snap, scroll-lock; bottom sheets (swipe to close, inner body scroll); Retina 2x/3x (no blur); mobile performance (heavy shadows/blur, 60fps); `prefers-color-scheme` (dark theme).
